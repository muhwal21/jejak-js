# Security Policy

jejak.js runs user code inside a browser Web Worker and has no server. The main risk is a way to escape that sandbox or to make a shared link run something the viewer did not expect.

## Reporting a vulnerability

Please **do not open a public issue** for security problems. Use [GitHub private vulnerability reporting](https://github.com/muhwal21/jejak-js/security/advisories/new) instead, with:

- what the problem is and what an attacker could do,
- steps or a share link to reproduce it.

You should get a reply within a week. Fixes are released as soon as possible and credited to you unless you prefer otherwise.

## Supported versions

Only the latest version on `main` (and the live demo) receives fixes.
